# 分段建造指南(超大规模建筑)

核心思想:**不要一次性生成 500³ 再渲**,而是切成段,每段渲染给视觉模型看,
像真实施工一样「堆一段、验一段、修一段」。

## 分段策略

| 策略 | 适用 | stage 划分方式 |
|---|---|---|
| **按层(bottom-up)** | 高层塔楼/公寓 | 地基→裙房→每 8-16 层一段→冠部 |
| **按翼(left-right)** | 横展的宫殿/街区 | 中轴线起,逐翼扩展 |
| **按功能** | 综合体 | 交通核→主功能体→附属体→表皮→环境 |
| **按系统** | 红石/机械建筑 | 先壳,再逐系统装机器(每系统一段) |

- 每个 stage 只放**该段负责的模块**,引擎自动处理与已放部分的碰撞/连接校验
- 段间连接尽量走**接口**(门/楼梯口/管道口),少依赖「贴墙摆放」
- 装饰件(树/路灯/招牌)放最后一段,别混在结构段里

## 检查点设置

- **首段必设检查点**:第一段定了基调和轴线,错了后面全错
- 每 3-5 段设一个;风格切换处(裙房→塔身)、连接复杂处(楼梯核)必设
- 检查点渲染建议:`iso,front,top` 起步;加 `--cut` 看内部时用 staged plan 的
  render 配置传 `{"views": "iso,right", ...}` 手动渲染剖面:
  ```bash
  python -m mcrender.cli staged_s02_floor1.schem --views right --cut x=N --scale 3
  ```
- 评审 prompt 焦点:「本段与已建部分的**衔接**」+「结构合理」,不要泛泛评审美

## 迭代节奏

```
写 stage → stage_build 跑 → 读 <stage>_review.md → 修模块或计划 → 重跑整个 plan
```
重跑很快(纯 numpy 装配秒级),渲染才是大头,所以:**先小图(scale 2)多迭代,定稿再大图**。

## 增量 litematic 的用法

每阶段输出的 `_diff.schem` 只含本段新增方块:
- 导入 Litematica 后可以单独**粘贴本段**(贴进已有施工现场)
- 两个版本的 diff 相减 = 看这次修改动了哪些格子
- 分发给合作者时,每段一个文件,避免重发整个建筑

## 红石/流体系统的分段

1. 复杂机器(计时器/水道/活塞门)先做成**独立模块**,单独渲染+单测后入库
2. 装配时用接口声明时序契约:spec.notes 写 `"in: 2tick脉冲 → out: 4tick后开门"`,
   装配计划的 stage note 写系统之间的接线关系
3. 跨模块红石线在交界处留 1 格**接头块**(红石粉/中继器),接口 origin 对准接头
4. 引擎只做几何对齐,不做时序仿真 —— 时序验收靠渲染图 + 人工(或视觉模型)检查接线

## 超大规模(>512³)的注意事项

- 装配网格自动扩容(128→256→512...),内存约 2B/格,512³ ≈ 268MB,可行
- 渲染器内存随四边形数涨;超大投影先 `--cut` 剖切渲染局部
- 一个 stage 的模块数控制在 50 个以内,方便出问题时定位
- 检查点评审图用小 scale,hero 大图只在最终验收出
